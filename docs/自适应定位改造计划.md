# 圆环测量：自适应定位改造计划

> 起因：换零件型号、或把零件挪出画面中心，就完全测不出尺寸。
> 本文记录 2026-10-07 的排查结论、当前管线里所有写死的先验，以及分阶段改造路线。
> 读者：后续接手的人 / AI 助手。行号对应 commit `2880d9d`。

---

## 1. 结论摘要

三条，按重要性排：

1. **今天「测不出来」不是几何先验造成的，是那一帧几乎全黑。** 实拍帧灰度均值 16.7，
   外圈射线只能找到 3/72 个边缘点。自适应搜索救不了一张没有边缘的图——先解决光照/曝光。
2. **自适应改造要解决的是「换型号 / 挪位置 / 改机位」**，让像素检测不再依赖
   「零件在画面正中 + 外圈半径 = 短边的 44%」这类写死的假设。
3. **自适应**不**解决毫米读数正确性。** `models/mm_per_pixel.json` 是「相机+镜头+拍摄
   距离」的函数，一个全图唯一常数。挪了相机高度，检测能成功、毫米数照样是错的。这一条
   必须由型号档案或重新标定来收（见 Phase 3）。

## 2. 目标与非目标

**做**：
- 零件不在画面中心时能测。
- 零件在画面里变大/变小（相机高度变化、换外径相近的型号）时能测。
- 换型号时，孔数、孔径、孔径比、沉孔特征不再写死（靠型号档案 + 相对约束）。
- 失败时**说清为什么失败**（太暗？找不到外圈？还是锁定置信度不够？），而不是笼统一句
  「外圈拟合失败」。

**不做**（明确排除，避免后面的人误期待）：
- **不解决没光。** 全黑帧、过曝帧、失焦帧，任何搜索策略都无解，只能靠补光/曝光/对焦。
- **不提升精度。** 单像素 ≈0.0327mm，5 丝(±0.05mm) ≈1.5px；当前机位斜视约 23°、沉孔缓坡
  边缘定位误差 ±3~5px，**达不到 ±0.05mm**。自适应只改「能不能测出来」，不改「测得准不准」。
- **不引入第三方依赖**（AGENTS.md §4）。
- **不动** `models/mm_per_pixel.json`、`gui_ring.py`、`测量.bat`。
- **不新建并列检测实现。** 几何算法一律改在 `fit_ellipse_ring.py`（AGENTS.md §6）。
  尤其**不要**从生产管线反向 `import profile_ring`——那会让管线依赖诊断脚本，方向反了
  （AGENTS.md §0 那条 gui_live 的教训）。

## 3. 现状诊断（2026-10-07 实测）

### 3.1 失败点

`debug\gui_error.log` 里当天的失败全是同一条，抛在 `src/measure_ring.py:132`：

```
MeasureError: 外圈拟合失败。检查：对焦、光照、零件是否在画面中心
```

调用栈是 `gui_ring.py:245 _do_measure → measure_ring.py:130 measure → measure_ring.py:132`。
即 `detect()` 的**第一关就返回了 None**（`fit_ellipse_ring.py:387-388`），
一个尺寸都没往下算。

### 3.2 实测证据

`gui_ring.py::LiveSource._do_measure` 在测量前会把相机原图存成
`data\captures\measure_ring_latest.jpg`（`gui_ring.py:240-244`），所以那张失败帧还在。
拿它和标定图跑**同一份** `detect()`：

| 指标 | 标定图 `capture_20260908_115557.jpg` | 失败的实拍帧 `measure_ring_latest.jpg` |
|---|---|---|
| 分辨率 | 4024x3036 | 4024x3036（相同） |
| 灰度均值 | 109.7 | **16.7** |
| 暗像素(<40) 占比 | 3.4% | **99.1%** |
| 亮像素(>200) 占比 | 5.2% | **0.0%** |
| 72 条射线找到的外圈边缘点 | **72 / 72** | **3 / 72** |
| `detect()` 结果 | 外圈拟合成功 | 外圈 = None |

`filter_and_fit` 需要 ≥20 个点才拟合（`fit_ellipse_ring.py:73`），3 个点直接判 None。
把那张帧调亮后目视确认：**零件确实在画面里、也基本居中**（就是那个带 6 个沉孔的法兰），
所以不是「零件不在视野」，纯粹是曝光不足。

### 3.3 时序：不是本次重构引入的

- 该错在 **15:56:03 / 15:57:18~15:57:30** 已批量出现，**早于**当天 16:50 起的任何代码改动。
- `gui_error.log` 里还有 **2026-09-18 11:18:24** 与 **2026-09-21 15:15:15** 两条同类失败
  （当时日志只记到 `NoneType: None`，是后来 commit `52e84d4` 才修好的日志缺陷）。
- 结论：这是**反复出现的老问题**，与 commit `2880d9d` 的三项清理无关——那三项已用
  「改前改后 CLI 输出逐字符一致」验证过（见该 commit 的 message）。

### 3.4 立即要做的（不属于本次改造，但挡在改造前面）

`src/config.py` 当前 `exposure_us=30000.0`、`gain=0`。要么现场补光，要么提高曝光
（150~200ms 起步）或加 gain，然后拍一张走 CLI 验证能出数：

```bash
cd vision-roughness
venv\Scripts\python.exe src\measure_ring.py --image ..\data\captures\<新拍的图>.jpg
```

### 3.5 一个会误导人的地方

窗口里的「预览增亮 ×3」**只作用于缩略图副本**（`gui_ring.py:255-269`，
`convertScaleAbs(small, alpha=3.0)` 作用在 resize 之后的 `small` 上），测量永远用相机原始
亮度。所以它会把一张 mean=16.7 的全黑帧显示成"灰蒙蒙还能看"，**别拿预览画面的亮度当
"曝光够不够"的依据**。这条建议写进 README 的操作说明。

## 4. 当前测量逻辑全景

`measure_ring.measure()`（`measure_ring.py:125`）调 `detect()`（`fit_ellipse_ring.py:365`），
四步，每步都带硬先验：

### 4.1 外圈（`:378-397`）

1. `sm = GaussianBlur(gray, (0,0), 5)`（`:376`）——σ=5 固定。
2. 从 **图像中心** + 初始半径 `min(w,h)*0.44` 起（`:379`、`:381`），失败再试 `0.40`、`0.48`
   共三档。
3. 每个半径：72 条射线，在 `[0.88·r0, 1.16·r0]` 窗口内找**最外侧的下降沿**
   （`mode="outer_first"`，`polarity=-1`，`min_grad=2.0`，`:382-383`）。
4. `filter_and_fit`（`:73`）：用"圆等价归一化距离 9%"滤离群点，`cv2.fitEllipse` 迭代 3 轮。
5. 精修：以粗椭圆中心/半径，紧窗口 `[0.93·req, 1.07·req]` 再采一轮（`:389-396`）。

**这是当前唯一的"全废"点**：这一关过不了，整个测量返回空（`:387-388`）。

### 4.2 中心孔（`:399-407`）

以**外圈中心**为原点，在 `[0.60, 0.78]·r_outer` 内找**上升沿**（暗→亮，`polarity=+1`，
`min_grad=1.2`，`:401`），同一套鲁棒拟合，内点半径锚定在 `0.7·r_outer`（`:402`）。
即**孔径/外径比写死在 0.60~0.78**。

### 4.3 6 个螺栓孔（`:409-446`）

1. 环带：外圈椭圆 ×0.98 与中心孔椭圆 ×1.05 之间（`:412-416`）。
2. 局部对比度归一化 `norm = sm / max(blur(sm,(201,201)),1)`（`:417`）。
3. `rough_templates`（`:111`）在环带里找暗连通域（`norm<0.62`、面积≥3000px²、圆度≥0.55），
   挑最像的当模板（±125px 窗口，强制 resize 到 250×250）。
4. `template_locate`（`:139`）：缩 3 倍做 `TM_CCOEFF_NORMED` 匹配，峰阈值 0.30，
   抑制半径 150px，最多取 12 个峰。
5. 候选过滤：距外圈中心必须在 `0.5~1.05·r_outer`（`:424`），且在 `(40,140)` 环带内
   找到 ≥12 个边缘点（`:426`）。
6. `hexagon_slots`（`:162`）：**固定 6 个孔、固定 60° 间隔、等归一化半径**，容差
   `tol_ang=13°`、`tol_r=0.15`；缺位按等角等半径推定（`:435-437`）。
7. 每个槽位 `measure_bolt`（`:348`）：`hole_head_center` 锚定螺丝头（`:201`，win=160,
   thr=0.72）→ `_head_radius` 估头半径（`:247`，12 方向，clip 到 0~60px）→
   `rim_cross_points` 找第一个宽度≥12px 的连续暗游程，取末端 **0.72 亮度阈值交叉点**
   作为沉孔口边缘（`:259`，72 射线，max_r=150）→ `fit_clean_arc` 极化残差鲁棒椭圆拟合
   （`:307`）。
8. 二遍校正：以拟合中心重采一轮再拟合（`measure_bolt` 内）。

> 领域提醒（AGENTS.md §5）：螺栓孔测的是**沉孔口口径**（含沉孔锥度），**不是螺纹孔径**。
> 6 孔读数分散 154.5~176.3px ≈ ±7%，**不得据此判定尺寸超差**。

### 4.4 换算与判定

- `mm = px × mm_per_px`，`mm_per_px` 是全图唯一常数（`measure_ring.py:113`、`:146`），
  来源 `--mm-per-px` / `--ref-mm` 标定后缓存 / 读 `models/mm_per_pixel.json`。
- `tilt = max(oa1,oa2)/min(oa1,oa2)`（`:161`），>1.02 就提示透视（`:162`）。
- **不传 `--spec-*` 时 `overall_judged=False`**，CLI 仍打印「综合判定: OK」——这个 OK
  不是合格判定（AGENTS.md §5）。
- 贴边检查 `BORDER_MARGIN = 5`（`:42`、`:148-149`）。

### 5.8 三条走查结论

1. **`init_c` / `init_r` 是从未被注入的死参数**（`:365` 定义，`:379`、`:381` 读取；
   全仓调用点只有 `fit_ellipse_ring.py:454` 与 `measure_ring.py:130`，都没传参）。
   → **这是自适应改造最现成的注入点。**
2. **仓库没有任何"型号 / 档案 / preset"概念**（grep `型号|profile|preset|nominal|part_type`
   只命中 `--spec-*` 单组标称值、`models/mm_per_pixel.json` 单个标量，
   以及 `profile_ring.py` 里表示"径向剖面"的 profile）。Phase 3 要从零建。
3. **`profile_ring.py` 里已躺着一整套自适应原语，但主流程从未采用**：
   `coarse_center`（`:16`，边缘密度质心）、`cross_projection`（`:28`，行/列投影峰定外圈 box）、
   `radial_hist`（`:65`，径向距离直方图）、`find_peaks`（`:76`，多半径峰）、
   `refine_center`（`:107`，网格搜索最大化峰高精化圆心）。
   `edge_ring.py:45-70` 另有 HoughCircles 多档 `param2` 扫描；`explore_ring.py:23-37` 有
   Otsu + 最大轮廓 + `minEnclosingCircle`/`fitEllipse`。
   → **借做法，不要借代码**（见 §2 的依赖方向约束）：把这些原语在 `fit_ellipse_ring.py`

### Phase 1：外圈自适应定位（收益最大）—— 方案与可行性验证

**做法**：新增"数据驱动粗定位"阶段，**现有的射线亚像素 + 鲁棒椭圆拟合一行不动**——
那部分已验证，只是"从哪儿开始找"写死了。

在 `src/fit_ellipse_ring.py` 内新增：

1. `_edge_map(sm)` —— Otsu 定阈值 → `Canny` 取边缘图（配方沿用 `profile_ring.py:125-127`）。
2. `_coarse_centers(edges)` —— 给出**多个**候选圆心而非只有图像中心：
   图像中心（保底）、`cross_projection` 式投影峰交点、边缘密度质心。
3. `_radial_peaks(edges, cx, cy)` —— 径向距离直方图 + 峰检测，得**若干候选半径**，
   替换写死的 `0.44/0.40/0.48` 三档。
4. 候选集 = `[旧先验(中心, 0.44×短边)] + [候选圆心 × 候选半径]`，**旧先验排第一**。
5. 每个候选走**现有**的 `find_edge_points(mode="outer_first")` + `filter_and_fit` + 紧窗口精修。
6. `_score_outer(...)` 硬门槛（模块级常量，便于调）：
   - 保留点数 ≥ `0.6 × 72`；
   - 角度覆盖无 >40° 的空洞（按射线角度分箱）；
   - 点到椭圆径向残差 RMS ≤ 3px（或 ≤ 半径的 0.3%）；
   - 长短轴比 ≤ 1.8，且椭圆不出画幅。
7. 选分数最高且过门槛者；**全不过就照旧失败**（保留诚实的 `MeasureError`），
   绝不在低分下硬给一个数。

**可行性已实测（2026-10-07，标定图，命令见附录 3）**：真实外圈中心为
**(1974.6, 1516.7)**，各粗定位原语给出的结果：

| 粗定位手段 | 结果 | 与真实中心距离 |
|---|---|---|
| `cross_projection` 投影峰 box 中心 | (1964, 1588) | **72 px** |
| `coarse_center` 边缘密度质心 | (2082, 1676) | **192 px** |
| 写死的图像中心（现状） | (2012, 1518) | 37 px |
| 径向直方图最强峰 | r=1305px（∅2610） | 与真实短半轴 2599.1 差 **0.4%** |

两个结论，直接决定 Phase 1 的做法：

1. **「用径向峰找外圈半径」这条路线成立**——最强峰和真实外圈只差 0.4%。
2. **但没有任何单一粗定位够用**：投影峰偏 72px、质心偏 192px，而采边窗口
   `[0.88, 1.16]·r0` 对 r0=1336 只给 **±160px** 余量——质心那种偏差会直接把窗口下界切掉。
   所以必须**多候选 + 图像中心兜底 + 打分选优**，而不是把某个粗定位结果直接替换进去。

**决定性实验（2026-10-07，型号 2 实拍 `capture_single_20261007_203729.jpg`，曝光已修好）**

盘心 (1412,1589)、画面中心 (2012,1518)——**偏了 604px**。同一张图、同一份 `detect()`：

| 喂给 `detect()` 的先验 | 结果 |
|---|---|
| 现状（图像中心 + 0.44×短边） | 外圈拟合**失败** |
| 注入 `init_c` / `init_r`（Otsu 粗定位） | 外圈「OK」：2962.9x3118.6px，但**只用上 22/72 个点** |

**看似通了，其实是误锁。** 真实盘径（径向峰 r=1289、峰宽仅 6px）是 **2578px**，
而这个拟合的均值直径 **3040px（大了 18%）**，外接框还**溢出画幅**
（x 到 −48、y 到 3174；画幅 4024x3036）。两条结论：

1. **先验确实是唯一的拦路石** —— 把它换对，检测立刻从「失败」翻成「通过」。
2. **但"随便给个粗定位"不够，反而更危险** —— 它会给出一个看着成功、实际偏大 18% 的椭圆。
   Phase 1 那几道门槛不是保险起见，是**必需品**：本例里「点数 ≥0.6×72」（22 < 43）
   和「椭圆不出画幅」任意一条都能把它挡下来。
   这也正说明为什么必须先有 Phase 0 的真值表——没有真值，你分不出「OK」和「误锁」。

**基线保护（关键）**：旧先验排首位 ⇒ 标定图必然走原路径，读数应逐位不变。
等 Phase 0 数据到位后再切"纯按分数选优"（Phase 1b），并确认标定图仍不变。

**顺带并入（约 10 行，直接解决今天的报错质量）**：`detect()` 前加亮度门——
动态范围太小时明确报「画面太暗（均值 x/255），先补光或提高曝光」，
而不是含糊的「外圈拟合失败」。

### 架构重构：拆掉 `feature` 枚举，改成两个正交维度（2026-10-08）

起因：`feature: countersink|core_hole` 把**两个本来独立**的决定压成了一个枚举——
「怎么定位孔」和「量哪条边界」。后果是组合爆炸：一旦出现「已知 4 孔角度 + 沉孔口边界」
这种组合，就得再加一个 feature 值、再抄一遍代码。而且代码的默认路径就是型号1 的样式，
等于把某一个具体产品固化成了系统的默认语义。

改法：拆成 `locate` + `boundary` 两个字段（各配一张策略表），**所有型号平级**：

| 维度 | 取值 | 说明 |
|---|---|---|
| `locate` | `profile_angles` / `template_ngon` | 按档案角度+相位搜索 / 暗斑模板匹配+n 等分校验 |
| `boundary` | `countersink_rim` / `dark_core` | 沉孔口阈值交叉 / 暗芯中分界 |

新组合（比如「4 孔沉孔」）现在**零代码**；全新形态（比如通孔）只加一个 boundary 函数（约 15 行）。

一并解决的几件事：

1. **孔数不再写死**：`ngon_slots(n=bolt_count)`；档案没给就用 `infer_ngon_n` 从候选峰推断。
   实测原来写死 6 时，12 孔零件下 6 个槽位**全被真孔填满、一个都不留空**——于是静默只报 6 个。
2. **推定位置标出来**（`src=detected|profile|synthesized`）：标定图里本来就有 1 个推定位置
   （螺栓孔5），以前和实测孔长得一模一样，现在报告写「← 位置推定」、GUI 加 `?`。
3. **中心孔没检出时螺栓孔照样跑**，不再整段跳过——那条「没检测到螺栓孔」的误导随之消失。
4. **全局缓存 `models/mm_per_pixel.json` 退休删除**：它是同一个数的第二份真相源，而且属于
   「上次标定的某个型号」。现在系数只存在型号档案里；查不到就**只报像素、不给毫米**。
5. **不传 `--profile` 用档案里的 `_默认型号`**（是数据，不是隐藏的代码路径），所以车间入口
   （`测量.bat` 不传参）照旧能用；`--ref-mm` 改为**必须显式带 `--profile`**，
   免得它落到默认型号、把那个型号的系数悄悄改掉。

验证：默认型号路径的**读数行与重构前逐字符一致**；型号2 读数不变；15 项自测全过。

### 型号识别（自动为主、人工兜底）—— 框架已就位，识别器待补

**要解决的问题**：以后型号多，不该让人每次去选型号；人工选择只作最后的兜底。

**为什么能用指纹识别**：绝对尺寸不行——`mm_per_px` 本身是按型号存的，拿绝对外径去查档案是
循环依赖。能用的只有**无量纲量**：孔数、有没有中心孔、孔圈半径比、孔径比。这些恰好都是像素
之间的比例，**不需要 mm/px 就能算**，所以识别可以在"没有档案"的前提下完成。

**流程（已实现）**：不传 `--profile` → 通用跑一遍取指纹 → `match_profile` 比对 → 唯一命中就用
该型号精测（若该型号正好走通用策略则复用这一遍，不白跑）；命中 0 个或 ≥2 个一律拒绝并说明。
`--profile <名字>` 仍是人工指定的兜底入口。

**它现在为什么命中不了（实测）**：取名"通用"的那一遍其实是不通用的——

- **型号2**：通用定位走的是暗斑模板匹配，要求暗斑面积 ≥3000px²（等效直径 ≥61.8px），
  而型号2 的暗芯只有 ~37px，**在第一关就被尺寸门槛挡掉**，孔数=0 → 无法识别。
- **型号1**：孔数推断被盘面上的假峰带偏，推出来的 n 不是 6 → 指纹对不上。

我又试了一版"不带型号先验"的圆特征查找器（环带内紧凑暗块、尺寸窗口用相对外径的比例），
实测在型号1 上只找到 **1/6** 个、型号2 上 **3/4** 个：局部对比度归一化的窗口（201px）和型号1
的沉孔尺寸（~170px）量级相当，等于把特征自己归一化掉了，而型号2 的特征又是另一个量级
——**必须多尺度**才覆盖得住，那不是小改，而且只有 2 个零件可调参（AGENTS.md §6 明确反对）。

**两条路线（待选）**：

1. **多尺度通用特征查找器**：在几个模糊尺度上各做一遍局部对比度归一化再取并集，特征尺寸
   窗口一律用相对外径的比例。能同时覆盖沉孔（6%OD）和暗芯（1.4%OD）。风险是要调参，而
   目前只有 2 个零件可验证。
2. **极坐标指纹匹配**（我更倾向）：每个档案存一张**参考指纹**——把环带按归一化半径展开成
   极坐标小图（360×N，几十 KB），识别时把待测图同样展开，再沿角度做归一化互相关求最佳
   匹配。优点：不依赖任何特征查找、天然抗旋转、只需要"外圈"这一个已经稳定的几何量；
   代价是每个型号要存一张参考图，且需要阈值（自匹配 vs 他人匹配）。

**现状（保证车间入口不挂）**：识别失败会落到 `_默认型号` 兜底，报告里**显式**写
「自动识别失败 → 按默认型号测量 → 请人工确认零件型号」，不静默冒充。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| **误锁（量错圈）比测不出来更糟** —— 操作员会拿着错数当真 | 硬门槛 + 必须报告"选了哪个假设/尺度/置信度"；低分绝不静默出数 |
| **基线漂移** —— 车间在用的这款零件读数变了 | 旧先验排候选首位；标定图回归门；逐阶段交付 |
| **实时性** —— 粗定位拖垮 7.7fps 取景 | 粗定位跑降采样图（Canny + 直方图），且仅在快速路径失败时才启用；预算 ≤100ms |
| **仓库没有测试框架**（AGENTS.md §3） | Phase 0 的评估脚本是替代品，但只放 `temp/`，不变成隐性新依赖 |
| **改完仍测不出，以为是改造没生效** | 先过 §3.4 的曝光/补光这一关；亮度门会把这种情况单独报出来 |
| **有人顺手引入平滑"提精度"** | AGENTS.md §6 已记：梯度算在未平滑剖面上，加平滑就是改所有读数 |
